# 从零理解红黑树 EasyX 前端：把“树”变成窗口里的圆和线

## 本章学习目标与前置知识

这篇文档假设你只学过变量、函数、循环、数组、类、构造函数和析构函数。你不需要提前懂 Windows 窗口编程，也不需要懂计算机图形学。读完后，你应当能完成四个可验证目标：

1. 能解释“红黑树算法”和“EasyX 界面”为什么应当分开。
2. 能说清一个节点从内存数据变成屏幕圆形所经历的数据流。
3. 能修改按钮文字、窗口尺寸、节点半径和示例数据。
4. 能自己增加一个“查找节点”按钮，而不是只会复制整份代码。

前置名词先拆开。

“前端”在本项目里不是网页。它只是用户能看到和点击的窗口部分：按钮、文字、线和圆。“后端”也不是服务器，而是红黑树数据结构。它负责插入、删除、查找和保持平衡。

“像素”是屏幕上的小点。EasyX 窗口左上角是 `(0, 0)`。横向向右，`x` 增大；纵向向下，`y` 增大。比如 `(100, 50)` 表示从左边走 100 像素、从上边走 50 像素。

“事件”是用户做了一件事，例如点击鼠标、关闭窗口。程序不会提前知道用户何时点击，所以它要循环等待消息。这个循环叫事件循环。

“渲染”在这里并不神秘，就是调用 `line` 画线、调用 `fillcircle` 画圆、调用 `outtextxy` 写字。把当前状态完整画到窗口上，就是一次渲染。

“快照”是某一时刻数据的只读副本。本项目不让界面拿到红黑树的真实节点指针，而是复制出键值、颜色和父子下标。这样界面只能观察，不能误改树。

## 形态分析：我们究竟在解决多大的问题

最简可交付界面只需要完成一个闭环：

用户点击按钮 → 输入整数 → 红黑树执行操作 → 读取树结构 → 计算坐标 → 重画窗口。

它不是游戏引擎，不需要摄像机、物理系统、复杂动画和多窗口。课程设计真正的核心约束有三个：

- 树必须真的调用参考头文件的插入和删除，不能为了好看在界面中伪造结果。
- 红色、黑色和父子关系必须与树的当前真实状态一致。
- 初学者应当能定位每一层职责，不能把所有逻辑堆进 `main()`。

因此，本项目最匹配的结构不是几十个类，而是三个小模块：

| 模块 | 输入 | 输出 | 不负责什么 |
| --- | --- | --- | --- |
| 红黑树 | 整数操作 | 树的真实状态 | 不知道窗口和像素 |
| 布局函数 | 节点快照 | 每个节点的 `(x, y)` | 不修改树，不画图 |
| EasyX 界面 | 鼠标消息、坐标 | 线、圆、文字 | 不实现旋转和颜色修复 |

这种拆分叫“关注点分离”。它不是为了显得高级，而是为了出错时能快速定位：插入后树错了，查树算法；结构对但位置错了，查布局；位置对但颜色没显示，查绘图。

## 对立转化：为什么不从“我要画一棵树”直接开写

顺向想法通常是：先开窗口，再画几个圆，最后把数据塞进去。这个方向容易得到“看起来像树，但与算法没有连接”的静态图片。

本项目采用终局反推。最终一帧需要知道每个节点的五项信息：值、颜色、父节点、左孩子、右孩子。于是先问红黑树能否安全提供这五项信息。原头文件只能通过迭代器获得值，无法恢复完整结构，所以新增只读快照接口。

这里还使用了“空间换确定性”：每次操作后复制一份很小的节点数组。它会多占一点内存，但课程演示通常只有几十个节点，这点成本几乎可以忽略。换来的好处是界面不保存真实指针，不会因为旋转或删除导致指针失效。

另一个逆向设计是每帧重新计算坐标，而不是维护“旧坐标如何移动到新坐标”。重新计算看似重复，却减少了大量动画状态。对最简课设来说，稳定比炫技更重要。

## 状态设计：让程序知道自己正处于哪里

程序长期保存的状态只有：

- `tree`：当前红黑树对象。
- `status_text`：底部提示，例如“插入成功：7”。
- `is_running`：窗口是否继续运行。

一次点击过程中会短暂出现：

- 输入框中的字符串。
- 转换得到的整数。
- `insert` 或 `remove` 返回的布尔结果。
- 当前帧的节点快照。
- 当前帧的节点坐标。

短暂状态用完就销毁，不放到全局变量里。尤其不能长期保存红黑树节点地址，因为插入旋转和删除都可能改变结构。

状态流可以写成：

```text
等待消息
  ↓
判断点击了哪个按钮
  ↓
读取并校验整数
  ↓
只调用 RBTree 的公开操作
  ↓
更新 status_text
  ↓
visualization_snapshot()
  ↓
calculate_positions()
  ↓
draw_scene()
  ↓
回到等待消息
```

## 阶段一：打破抽象——EasyX 为什么存在

### 1. 它解决了什么工程痛点

Windows 原生窗口程序需要注册窗口类、创建窗口、处理窗口过程、获取设备上下文并调用 GDI 绘图。对刚学习数据结构的学生来说，这些内容会淹没“红黑树”本身。EasyX 把常用流程封装成 `initgraph`、`line`、`fillcircle`、`outtextxy` 和消息函数，使你能把注意力放在数据如何映射为图形。

### 2. 如果没有这层封装会怎样

没有 EasyX 并不意味着计算机不能画图，而是你必须直接面对 Windows 消息和绘图资源。一个简单的圆可能需要处理窗口句柄、重绘消息和画刷生命周期。若忘记释放 GDI 对象，程序可能逐渐耗尽图形资源；若阻塞窗口消息，窗口会显示“未响应”；若只画一次而不处理重绘，窗口被遮挡后内容可能消失。

具体到本项目，如果把红黑树删除修复和原生窗口过程写在同一个函数里，你会同时追踪叔叔节点、兄弟节点、鼠标坐标和窗口消息。任何一个分支出错都难以判断原因，这就是认知上的“灾难”。

### 3. Linux 底层与 Windows 底层对应什么

EasyX 主要面向 Windows，并不是 Linux 图形库，所以这里没有一个对应的 Linux 系统调用。Windows 侧底层接近消息队列和 GDI：鼠标、键盘、关闭窗口等消息进入线程消息队列，EasyX 帮你取出消息；画线和圆最终需要操作窗口的图形设备。

Linux 桌面同样不会只靠一个 `draw_circle` 系统调用完成绘图。常见方案是 X11、Wayland 上层工具包或 SDL/SFML，它们再与显示服务器和内核设备协作。应当记住：图形库是跨在“你的业务数据”和“操作系统图形机制”之间的一层封装，不要把 EasyX 函数误认为 C++ 标准库。

## 项目源码映射

### `reference-projects/red-black-tree-template/rbtree.h`

这是数据结构层。界面只调用：

- `insert(value)`：插入整数。
- `remove(value)`：删除整数。
- `visualization_snapshot()`：获取只读绘图数据。

新增的 `VisualizationNode` 使用下标而不使用公开指针。`left_index == -1` 表示没有左孩子，`right_index == -1` 表示没有右孩子。根节点的 `parent_index == -1`。

这是一种教学友好的简化。潜在代价是每次绘图都复制节点，节点数量非常大时效率不如直接遍历，但课程演示规模下更安全。

### `src/tree_visualization_model.h` 与 `src/tree_visualization_model.cpp`

这是后端适配层。它持有 `RBTree<int>`，负责调用插入、删除和查找，并把快照换算为带屏幕坐标的 `VisualNode`。这两个文件不包含 `graphics.h`，因此即使没有安装 EasyX，也能独立编译和测试。

### `src/easyx_frontend.cpp`

这是最后一层的新入口，完全不引用原版 `main.cpp`，也不直接操作 `RBTree<int>`。

`Button` 只做矩形点击判断。`draw_tree` 只消费后端给出的 `VisualNode`。`draw_scene` 负责整帧，`read_integer` 负责输入校验，`main` 只组织模型生命周期和事件循环。构建脚本也把该文件放在后端源文件之后。

### `build_easyx.ps1`

这是构建脚本。它寻找 Visual Studio 的开发环境，然后用 MSVC 编译 `easyx_frontend.cpp`。当前机器虽然安装了 Visual Studio 2022 C++ 编译器，但还没有 EasyX 的 `graphics.h`，因此首次构建前必须安装 EasyX。

官方安装页：<https://easyx.cn/setup>

安装后，在 PowerShell 中进入项目根目录并执行：

```powershell
.\build_easyx.ps1
```

成功后运行：

```powershell
.\bin\easyx_red_black_tree.exe
```

## 阶段二：理论落地——200 到 500 行 MVP 拆解

当前 `easyx_frontend.cpp` 就是 MVP。建议不要从第一行到最后一行死背，而是按自底向上的顺序重做。

### 第一步：只开窗口

建立 1100×720 的窗口，画一句标题，然后关闭。验收标准是窗口能出现且不会立刻闪退。

### 第二步：只画一个固定节点

不用红黑树，固定在 `(550, 200)` 画黑圆并写入 `10`。这一步学习坐标、颜色、文字居中。

### 第三步：画固定父子关系

先画一条线，再在两个端点画圆。你会理解为什么“先画线、后画节点”：节点圆会覆盖线的末端，视觉更整洁。

### 第四步：接入快照

插入 `10、5、15`，打印或断言快照长度，确认根的父下标为 `-1`，左右孩子下标有效。先验证数据，再画图。

### 第五步：加入布局

递归遍历左孩子、当前节点、右孩子。每访问一个节点就增加序号。序号决定横向排列，递归深度决定纵向层级。

边界坑点包括：空树不能访问下标 0；只有根节点时最大深度是 0，除法时要避免除以 0；节点太多时圆会重叠；极大的整数文字可能超出圆。

### 第六步：加入按钮和输入

按钮点击后弹出 `InputBox`。输入先以字符串存在，再通过 `wcstol` 转成整数。不能直接认为用户一定输入数字，空字符串和 `12abc` 都应拒绝。

### 第七步：加入重置

参考 `RBTree` 没有 `clear()`，且默认复制会造成指针所有权问题。因此当前代码删除旧对象、创建新对象，再插入示例值。构造函数与析构函数在这里不是考试名词，而是实实在在地管理整棵树的生命周期。

## 阶段三：硬核通关——数据流追踪

假设当前树有 `10、5、15`，用户点击插入并输入 `7`：

| 时刻 | 关键变量 | 值 | 含义 |
| --- | --- | --- | --- |
| T0 | `message.message` | `WM_LBUTTONDOWN` | 收到鼠标左键按下 |
| T1 | `value` | `7` | 输入框转换成功 |
| T2 | `inserted` | `true` | 红黑树接受新值 |
| T3 | `status_text` | `插入成功：7` | 界面反馈已更新 |
| T4 | `nodes.size()` | `4` | 快照包含四个节点 |
| T5 | `positions` | 四组坐标 | 布局计算完成 |
| T6 | 窗口 | 新树形 | 批量绘图刷新 |

验证快照的命令：

```powershell
g++ -std=c++14 -Wall -Wextra tests\rbtree_snapshot_test.cpp -o bin\rbtree_snapshot_test.exe
.\bin\rbtree_snapshot_test.exe
```

程序无输出且退出码为 0，表示断言全部通过。也可以临时在测试中故意把 `left_index` 的比较方向写反，观察断言失败，理解测试不是装饰。

EasyX 使用批绘图：`BeginBatchDraw()` 后绘图先进入缓冲，`FlushBatchDraw()` 再一次显示。若每画一条线就立即显示，频繁重绘可能产生闪烁。

## 常见误区与实验作业

### 误区一：界面必须继承红黑树

错误。界面“使用”红黑树，不是红黑树的一种。实验：尝试用一句话读出“EasyXWindow is a RBTree”，你会发现语义不成立；正确关系是“窗口拥有一棵树”。

### 误区二：能迭代所有值就能恢复树结构

错误。同一组有序值可能形成多种树形。实验：比较 `10、5、15` 与其他插入次序形成的结构，只看值集合无法确定父子关系和颜色。

### 误区三：直接公开 `root` 最省事

短期省一行，长期会允许界面修改根指针、颜色和孩子。实验：设想按钮误写 `root->left = root`，递归析构和遍历都会陷入严重问题。快照接口正是为了堵住这种破坏路径。

### 误区四：节点坐标属于红黑树类

错误。坐标取决于窗口大小和布局策略，不是红黑树数学性质。实验：把窗口宽度从 1100 改成 800，树的键值和颜色不应变化，只有坐标变化。

### 误区五：删除节点后只擦掉一个圆即可

错误。删除修复可能旋转并重新着色，多个节点的位置都会变化。实验：删除不同黑节点，观察整棵树重新布局。最简实现每次全量重画更可靠。

### 误区六：输入框返回的一定是数字

错误。实验：输入空串、负数、`12abc` 和超长文本，记录程序反应。输入边界是界面的一部分。

### 误区七：窗口没有动画就不算图形化

错误。图形化的最低标准是用可视元素表达真实状态并接受交互。动画是增强项，不应反过来拖垮数据结构正确性。

作业一：修改主题。目标是改变背景、按钮和节点颜色；提示是搜索 `RGB`；预期现象是功能不变而视觉改变。参考实现就是只替换颜色常量。

作业二：增加查找按钮。目标是输入一个值并提示存在或不存在；提示是增加一个 `Button`，点击后调用 `contains`；参考实现不需要修改红黑树；预期现象是树结构不变，只更新状态栏。

作业三：限制节点数量。目标是超过 31 个节点时拒绝插入；提示是读取快照长度；预期现象是避免节点过密。参考实现可在调用 `insert` 前判断 `visualization_snapshot().size()`。

作业四：高亮刚操作的节点。目标是插入或查找后用黄色边框标记；提示是新增 `highlight_value` 状态并在画节点时比较键值；预期现象是下一次操作更新高亮。

作业五：固定序列逐步演示。目标是为 `A L G O R I T H M` 增加“下一步”；提示是用数组保存字符、用下标保存进度；参考实现每次点击只处理一个元素；预期现象是能逐帧展示课程要求。

## 延伸项目

EasyX 适合快速完成 Windows 教学界面，但它不是跨平台 GUI 框架。若以后想扩展：

- SFML：比 Qt 小，适合二维绘图和事件循环，跨平台，迁移当前“状态—布局—渲染”结构较自然。
- SDL：更接近底层，多媒体能力强，但文字绘制需要额外组件，初学门槛略高。
- Qt：适合完整桌面软件，按钮、输入框和布局系统成熟，但工程概念明显更多，不适合一天内第一次接触图形化时强上。
- Graphviz：特别适合自动布局树和图，但交互性弱，更像生成结果图。
- TinyWebServer、muduo、tinyhttpd、CS144：这些是网络方向项目，不是 EasyX 的直接下一站。它们值得学习状态机和模块解耦，但不应为了给红黑树画图而引入。

客观路线是：先完成当前 EasyX MVP，再加固定序列步骤演示；课程结束后用 SFML 重写绘图层，保持 `RBTree` 和快照接口不变。若两套界面都能复用同一数据层，你才真正理解了解耦。

```markdown
# 红黑树 EasyX 前端复盘

## 核心目标
让用户通过按钮操作真实红黑树，并把父子关系、键值和红黑颜色绘制到窗口。

## 架构
1. RBTree 负责插入、删除、查找和平衡。
2. visualization_snapshot 只读复制绘图数据，不暴露真实节点指针。

鼠标点击 -> 输入校验 -> RBTree 操作 -> 更新提示 -> 获取快照 -> 计算坐标 -> 整帧重绘。

## 关键经验
界面不应直接修改树节点；删除后应重新读取整棵树；最简课设先保证正确交互和真实可视化，再考虑动画。

## 验证
用 tests/rbtree_snapshot_test.cpp 验证快照父子下标、左右键值关系和删除后数量；安装 EasyX 后运行 build_easyx.ps1 构建窗口程序。
```
