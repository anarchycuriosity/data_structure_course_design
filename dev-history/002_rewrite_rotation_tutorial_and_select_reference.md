# 002 降低旋转学习门槛并筛选参考项目

## 问题

原教学文档仅用“右孩子上位”概括左旋，随后迅速进入插入修复和删除修复。对尚未建立树、子树、父指针和根指针概念的读者，这会造成明显跳步。读者可能背下旋转方向，却无法解释中间子树去了哪里，也无法定位代码为何丢节点。

## 形态分析

红黑树项目代码规模不大，但指针和颜色约束密集。旋转不是一个可略过的术语，而是插入、删除修复共同依赖的结构原语。因此文档需要把它拆成独立学习阶段，并把结构验证先于完整红黑性质验证。

## 对立转化

没有继续增加案例编号，而改用终局驱动判断：希望右孩子上升就左旋，希望左孩子上升就右旋；折线先拉直，再处理直线。用 `α、β、γ` 子树证明中序不变，减少机械记忆。

## 状态设计

为每次旋转规定中序序列、节点数量、外部父亲、总根、父指针、环和中间子树七类检查。为后续项目规定每次操作输出日志并运行验证器，避免只凭 GUI 图形判断正确性。

## 参考项目筛选

通过 GitHub 官方 API 筛选 C++、MIT 许可红黑树项目，并在临时目录检查源码和构建情况。

- 排除 `sandeepnmenon/Red-Black-Tree-Implementation`：示例将实现文件直接包含到主文件，若同时编译两个源文件会产生重复定义；代码也存在较多不适合作为新手规范的写法。
- 选择 `Henrik-Peters/Red-Black-Tree`：仓库小，包含插入、删除、左右旋、性质检查、大量测试和 Graphviz 输出，许可证明确。
- 限制：选中项目自述偏重性能而非易读性，并使用不符合本项目规范的命名和格式。因此只作为行为、测试和可视化参考，以 Git 子模块隔离，不将其风格引入本项目源码。
- 本机验证：C++17 编译成功，插入规模到 1000 的测试通过；原测试在 Windows 默认栈下运行到 100 万元素案例时栈溢出，原因是测试函数使用大尺寸栈数组。把链接栈增大到 32 MiB 后，40 项测试全部通过。正式借鉴时仍应将压力测试数组改为堆上容器，不能把这个参考项目当作跨平台模板原样提交。
