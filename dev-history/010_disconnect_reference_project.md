# 010 彻底解除主项目对参考项目的依赖

## 问题

虽然图形界面已经使用 `src/rbtree.h`，但数据测试脚本仍然直接编译 `reference-projects/red-black-tree-template/main.cpp`，并且参考项目仍以 Git 子模块存在。这意味着参考目录并非纯粹“观看和参照”。

## 形态分析

真正独立需要同时满足：

1. 源码包含关系不指向参考目录。
2. 构建脚本不读取参考目录。
3. 测试入口不读取参考目录。
4. Git 克隆主项目时不需要初始化子模块。
5. 临时删除参考目录后，图形化和数据测试仍能通过。

## 对立转化

主项目原本已有与参考 `main.cpp` 字节完全一致的 `src/main.cpp`。将它正式纳入 Git，并把测试构建脚本改为编译 `src/main.cpp`。红黑树继续使用已经复制到主项目的 `src/rbtree.h`。

参考目录从 Git 子模块转换为普通文件目录，删除 `.gitmodules` 和 gitlink。它不再代表另一个仓库的特定提交，只是一份供阅读的源码快照。

## 状态设计

- `src/rbtree.h`：唯一参与主项目编译的红黑树头文件。
- `src/main.cpp`：主项目数据测试入口。
- `src/easyx_frontend.cpp`：主项目图形入口。
- `reference-projects`：纯参考资料。

最终验证会把参考目录临时改名，使其在文件系统中不可见，然后分别运行数据测试构建和 EasyX 构建。如果两者通过，才能证明依赖真正解除。

测试脚本最终命名为 `build_data_tests.ps1` 与 `run_data_tests.ps1`，避免名称继续暗示主项目需要参考仓库。
