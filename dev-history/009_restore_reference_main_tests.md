# 009 恢复参考项目 main.cpp 数据测试

## 问题

此前为了精简图形化项目，头文件中的终端字符串、Graphviz 输出和 `toString()` 接口被停用。原版 `main.cpp` 文件虽然仍然存在，但其中大量断言需要 `toString()` 比较树形，因此无法继续作为完整测试入口。

## 形态分析

图形化演示和数据测试不是互相替代的关系：

- EasyX 负责让人观察和操作树。
- 原版 `main.cpp` 负责批量验证插入、删除、不变量和迭代器。

只保留前者容易出现“界面看起来正常，但边界情况没有验证”的问题。

## 对立转化

恢复参考头文件中被停用的调试接口和相关标准库依赖，不修改原版 `main.cpp`。主项目 `src/rbtree.h` 随后重新从参考项目逐字节复制，保证图形化和测试使用同一份算法逻辑。

## 状态设计

- 图形化构建：`build_easyx.ps1`。
- 图形化运行：`run_easyx.cmd`。
- 测试构建：`build_reference_tests.ps1`。
- 测试构建并运行：`run_reference_tests.ps1`。
- VS Code 测试任务：`Run Reference Tree Tests`。

原测试包含一百万元素的栈上数组，因此链接时把 Windows 栈空间增大到 32 MiB。测试使用 `gnu++14`，因为原版测试宏包含 GNU 语句表达式扩展。
